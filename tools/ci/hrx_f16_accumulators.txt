# f16 fragment accumulators updated by a multiply (engine#2186 item 1, engine#2167).
#
# This is the third shape that loses a value to half precision, and the only one a truncation scan cannot see: the
# accumulator IS f16, so there is no `fptrunc` to find. The sum over the reduction leaves 65,504 long before any single
# input does -- engine#2167's case fails at activation_scale=10000, well below the f16 overflow point, because k=256
# terms of that magnitude accumulate past it.
#
# One line per .loom that has such an accumulator. `tools/ci/hrx_f16_narrowing.py --write` regenerates both this file
# and tools/ci/hrx_f16_narrowing.txt; a new entry is drift the ratchet refuses, and a line whose file no longer has a
# mul-updated f16 fragment is stale and should be dropped as the corpus is fixed.
