# Targets whose add_test() names them and which ci.yml's --target list never builds (engine#1595).
#
# These tests report "Not Run" in CI today: ci.yml's own comment says a test whose binary is missing is
# reported that way, and the job stays green. That is the defect this file ratchets rather than gates.
#
# The check FAILS when this set GROWS - a new name here is a change that broke something, and it is
# named in the output. A name that DISAPPEARS is progress and is reported as such, so this file can be
# deleted a line at a time. It is a SET, not a count, because a count passes a rename (#1595).
#
# How a target counts as named, which is where the number comes from: a bare token in the COMMAND
# (`COMMAND plain_test`) OR a generator expression (`$<TARGET_FILE:plain_test>`). Both mean the test
# cannot run unless CI builds the target. By the bare-token rule alone the numbers are need=62, drift=35
# (the figure in #1595); adding the generator expressions gives need=64, drift=36, the two extra being
# npu_derive_designs_dump (a real gap the bare rule missed) and onebit (which ci.yml does build).
#
# Script tests (COMMAND sh/bash/python3 ...) are not here on purpose: they need no build, so they are not
# in `need` at all. That is also why a self-test runner can live in an add_test for free (engine#1596).
