# 315-fa-masked-v-nonfinite

The discriminating experiment for section 25's surviving hypothesis, at the cost of a test case
rather than a campaign. The fork's suite (27 cases, commit `e6187096b`) rewrites the masked K/V rows
five ways - random, `+x`, `-x`, `+0`, `-0` - and requires bit-identical output, which can only betray
a leak by a fraction of an F16 ulp. This extension adds three variants that put **NaN, `+inf` and
`-inf` into the masked V rows**.

Why that is a valid detector and not a false positive: V reaches the output only as `P*V`, and the
Oct 2 design zeroes the V rows of masked keys, so a correct kernel never multiplies by the value
sitting there - including when it is NaN, because the zeroed row is exactly `+0`. A kernel that still
consumes masked V rows produces NaN/inf in the output instead of an ulp. Masked K is deliberately
left finite: the masked score is `raw + mask` with `mask = -inf`, and `-inf + NaN` is NaN, so a NaN
masked K row poisons even a correct kernel.

Two details make the detector airtight rather than merely plausible:

1. **The rewritten rows are masked for *every* query row.** The loop starts at
   `kv_row * c.visible`, and the case's causal mask puts row `r` at position `visible - queries + r`, so
   every `cell >= visible` satisfies `cell > position` for every row and is masked out for all of them.
   There is therefore no legitimate path by which one row's contribution could need those V values -
   the "a key masked for one row but visible for another" case, where `0 * NaN` would be a correct
   result, cannot arise here.
2. **Those rows are already proven reachable.** The suite's own history records the finite variants
   failing 5 of 27 cases before `e6187096b`, on these same rows: the rows past the sequence end demonstrably
   reach the V path. The non-finite variants only make an existing sensitivity louder, they do not
   create a new one.

The prefill kernel's rule is worth watching separately here: it zeroes keys that no row of the tile gives
any probability, which is the same set, so its expectation is identical - but a residual hole there would
show up as non-finite output only in the prefill cases (`q >= 16`).

Expected outcomes, pre-registered:

| outcome | reading |
|---|---|
| all cases pass, `non-finite outputs 0` | the decode-split and prefill kernels do not consume masked V rows in any of the covered shapes; section 25's hypothesis is dead and the producer is elsewhere |
| any case reports non-finite outputs | the kernel consumes rows the mask hides: the mechanism is named at kernel level, and the fix is to stop letting the visibility predicate decide whether those rows are zeroed |
| a case that already differed on the finite variants now differs harder | the leak is the Oct 2 class returning, not a new one |
